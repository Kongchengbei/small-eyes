## 2. 可直接用于报告的系统说明

系统采用 RV32IM CPU，整机配置包含指令与数据 Cache、动态分支预测、DDR 存储、双路摄像头采集、ROI 前处理、RGB565 到 INT8 转换和 NPU 推理模块。CPU 负责启动、配置和结果管理，图像处理与推理由相应硬件模块执行。各模块的具体设计贡献由团队在报告中统一确认。

工程通过 menuconfig 管理硬件配置、程序路径和相关生成参数。配置工具统一处理地址映射、BSP 定义和受管理的时序约束；BRAM 配置还会生成指令 RAM 初始化参数，减少手工同步配置时出现的不一致。

目前已经完成最新 Full DDR 配置的静态编译、lint 和 PDS 全流程，生成了位流。该位流尚未烧录，因此尚无对应的启动、DDR 训练、识别率、识别延迟或新 CoreMark 实测结论。

## 5. menuconfig 与“同一套 CPU”的准确说明

### 5.1 两种配置的关系

| 项目 | BRAM 评测/小程序配置 | Full DDR 应用配置 |
|---|---|---|
| 配置入口 | `SOC_PROFILE_BRAM` | `SOC_PROFILE_FULL` |
| CPU 模块来源 | 共用 `cpu/Htop.v` 及相关 CPU 主体 RTL | 共用同一套 RTL |
| 存储接入 | 片内指令/数据 RAM IP | ICache、DCache 与 DDR |
| RAM 容量 | IRAM 32 KiB、数据 RAM 16 KiB | DDR 地址划分见配置头 |
| 取指参数 | `CONTINUOUS_FETCH=1` | `CONTINUOUS_FETCH=0` |
| 摄像头、NPU、DDR 控制器 | 不实例化完整应用分支 | 按整机配置接入 |
| 程序加载 | 程序转换为 HEX/DAT，随位流初始化 IRAM | Flash 程序与模型按启动配置搬运 |

这是一套 RTL 的参数化构建选择。保存配置后，综合时通过参数和 `generate` 选择实现；切换配置需要重新生成位流。它不等于板上运行时仅把几个外设使能拉低。BRAM 模式还切换了存储系统、Cache 实例和部分取指控制，因此两种配置的综合网表不能宣称完全相同。

通用 CPU 优化在共用设计中实现。BRAM 配置适用于容量范围内的小程序，并非只能执行 CoreMark。报告应将“共享 CPU 设计”与“配置不同”同时写清楚，不通过隐去存储和取指差异来说明评测条件。

### 5.2 可直接放入报告的文字

> 系统采用统一的参数化 CPU RTL，通过 menuconfig 生成应用配置与处理器评测配置。应用配置接入 Cache、DDR、摄像头和 NPU；评测配置使用片内 BRAM，并在综合阶段裁剪无关外设。两种配置共享 CPU 主体设计，存储接入和部分取指控制根据配置选择。通用 CPU 优化在共用设计中实现，CoreMark 结果同时记录测试配置、CPU 频率、编译选项和实现版本，便于复现与比较。

## 6. 可用于报告的开发过程

### 6.1 设计流程文字（控制在模板200字以内）

> 先完成CPU、Cache及总线设计，再接入双路摄像头、前处理和NPU。通过menuconfig管理应用与评测配置，统一生成相关参数。随后结合静态检查和PDS报告定位长路径，优化地址生成、参数校验及缓冲统计，并完成整机时序闭合。最后以板上运行补齐性能和识别数据，归档配置、源码及结果。

### 6.2 CPU 通用优化

已有开发记录包括乘法提前启动、除法早退、前递路径调整、返回地址栈、BTB 更新以及 Cache 取消路径优化。后续 CPU 时序工作将宽数据选择和晚到控制分开，调整重定向、CSR 计数器与异常控制等路径。没有增加执行流水级，相关内容按通用 CPU 优化描述。

这些是实现内容与开发过程，不直接等同于最新实测跑分提升。历史分数之后还发生过 CPU RTL 修改，最新性能需要重新板测。

### 6.3 NPU/缓冲时序优化

本轮对模型头、旧模型 scratch、层参数与尺寸校验分拍；权重读地址改用运行基址，张量地址与有效位判定分开；INT8 空闲容量改用精确寄存计数，非法归还统计拆分事件与基础计数。模型文件、量化规则和 MAC 主循环吞吐设计保持不变，尚无本轮端到端板测结果。

以下为同一 CPU/DDR 频率下的实际 PDS 记录。第2轮包含按厂商 IP 参考恢复时钟分组的修改，因此表格展示整个闭合过程，不把全部改善都归因于 RTL。
