# 待确认问题回复

| 方向            | 当前结论                                                     |
| --------------- | :----------------------------------------------------------- |
| 1．输入尺寸     | 等待B测试、暂不修改现有96×96配置。                           |
| 2．颜色与排列   | 颜色顺序确定为RGB。按每像素`R、G、B、0`存储                  |
| 3．输入数值     | RGB565按高位复制展开成8位颜色，再减128；使用8位补码，范围**−128～127**。B据此训练并提供标准测试数据。 |
| 4．独立INT8缓冲 | 志勇提出容量、数量、对齐和小图间隔需求，赵振翔审核并统一分配DDR地址（当前为4*2)起始地址：0xB8800000（soc_addr_map.vh） |
| 5．控制与交接   | CPU负责初始化、配置和总体启动。启动后，两路前处理、INT8转换和共享NPU按照硬件接口持续运行，CPU不逐批启动任务、不确认正常交付，也不逐批下达缓冲归还命令。需要软件介入的异常由硬件保持错误状态并通知CPU。每批数据保留摄像头编号、帧token、缓冲编号、数据地址、小图数量及顺序。交付信息必须保持到下游接收成功；接收成功不等于缓冲可以归还。INT8转换模块开始一批转换前，自行检查并占用能够容纳整批小图的空闲INT8缓冲。没有空闲缓冲时等待，不覆盖已有数据，也不将正常等待直接当作硬件错误。第一版沿用RGB565缓冲的整批归还方式。整批INT8转换成功、DDR写入确认完成且不再读取RGB565数据后，由转换模块归还对应RGB565缓冲。归还不等待NPU启动、推理完成或最终结果读取。NPU侧管理逻辑确认该批INT8输入不再被读取、相关读取事务已经结束后，归还对应INT8缓冲。归还必须核对缓冲编号和帧token，拒绝过期或不合法的归还。结果所需的元数据独立保留，不因图像缓冲归还而丢失。CPU可以执行总体停止、异常恢复和重新启动。停止对应摄像头采集时，硬件必须安全处理在途DDR事务、半帧及FIFO残留；下游继续处理已有任务，恢复采集后从完整新帧开始。主动丢帧与硬件错误分别记录。超时或报错不得导致仍被访问的缓冲提前复用。 |
| 6．时钟         | 第一版沿用现有整批RGB565缓冲管理。若实测占用时间影响采集，再单独批准逐张归还改造。小图生成、INT8转换统一使用`ddr_core_clk`；沿用现有复位方式。 |
