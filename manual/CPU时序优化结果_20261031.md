# CPU 时序优化结果（2026-10-31）

后续更新：DDR 时序优化已完成，当前结果见 [DDR时序闭合结果_20261031.md](DDR时序闭合结果_20261031.md)。以下数据保留为 CPU 接入/优化阶段的历史记录。

在当前 Full DDR SoC 中，CPU 保持 70 MHz，slow setup WNS 从初次接入的 -0.853 ns 提升到 **+0.271 ns**，TNS 从 -94.381 ns 归零，失败端点从 467 归零。CPU 两个工艺角的 setup、hold、recovery、removal 和最小脉宽均通过。PDS 全流程完成，位流已生成，未烧录。

**整机时序仍未闭合**：DDR core setup WNS -2.485 ns，TNS -9417.415 ns，10455 个失败端点；DDR/PHY 跨时钟复位 recovery 仍有违例。不能将 CPU 通过写成整机通过。本轮目标是 CPU 时序，未修改 DDR/NPU RTL 或约束。

## 改动及原因

- ID/EX 前递的数据选择由已经登记的生产者归属决定；有效信号、依赖匹配和 ready 继续限制发射、访存及 CSR 副作用，缩短晚到的 Cache 响应控制路径。
- 跳转预测匹配提前计算两种条件的期望；重定向地址分量先采样再组合，宽 PC 载荷与取消/有效控制分开。DDR 的作废信号与已有 ICache 取消周期对齐，BRAM 保留即时重定向请求。
- BTB 训练延后一拍，返回地址栈的数据写入与指针/深度状态分开；清空后无效载荷不可见。
- CSR 计数器拆分低半部进位；中断 pending 条件提前合并。mtval/mcause 用少量状态标志选择常量或软件数据，避免晚到的 trap 控制驱动整组 32 位寄存器。
- 乘法部分积每拍采样，由 valid 保持原有结果与完成时序；ID→EX 载荷不再依赖晚到的异常清除信号，架构有效位仍保留清除优先级。

没有增加执行流水级；没有为 BRAM 单独开启一套 CPU 优化。分支预测训练时机发生变化，性能必须重新板测，不能沿用历史分数作为新成绩。
