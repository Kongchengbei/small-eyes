# CPU 分批优化实施记录

开始日期：2026-10-25，后续验证持续到 2026-10-26。工作分支：`main`。CPU 保持 70 MHz、单发射、五级流水线。

本轮按用户要求直接实施，不再等待逐项人工 review。Luna high 编写 BTB 返回类型元数据、8 项返回地址栈和除法早退候选；主代理负责执行策略统一、流水线接入、实际差异审查与 PDS 检查。双发射不纳入第二批。

## 第一批范围

1. 保留已经实现的通用乘法提前启动。满足操作数依赖和握手条件时，在 ID 发射沿启动部分积。BRAM 和 DDR 使用相同条件。
2. 统一 ID 执行策略。分支和 JALR 使用相同的 EX/MEM 前递；普通消费者可以携带紧邻 load 的 pending 标记进入 EX。EX 等待匹配数据，并在背压时保存已返回的值。移除 `Hidu.BRAM_MODE`，禁止按存储模式启用这些执行优化。
3. 保持 16 项直接映射 BTB。静态词面统计不足以证明动态替换，简单 XOR 索引也没有充分收益依据，因此不扩容、不改索引。详见 [BTB 索引审计](CPU优化运行记录/00_BTB索引审计.md)。
4. 新增 8 项返回地址栈（RAS）。只在 ID 实际发射时更新；EX 异常、中断或 MRET 重定向清栈。ID 自身误预测不会清掉本次调用或返回的更新。空栈回退 BTB，满栈覆盖最老记录。

RAS 按 [RISC-V RV32I 规范](https://docs.riscv.org/reference/isa/unpriv/rv32.html) 的 `x1/x5` 提示识别调用和返回。JALR 非零立即数仍更新栈，但使用 BTB 目标，避免将未经偏移调整的栈顶当作目标。

## 存储配置的边界

IMEM/DMEM 与 ICache/DCache/AXI 仍由 menuconfig 选择。固定延迟 BRAM 的连续取指与变延迟 cache 的取指握手仍有不同控制。这些取指接口差异没有在本轮合并；不能据此宣称两个配置的所有前端控制都已完全相同。本轮统一的是前递、load 依赖处理、乘法提前启动和新增预测功能的执行条件。

## 第二批范围

增加通用 DIV/REM 早退，不增加发射宽度。依次保留除零和 `INT_MIN / -1` 既有结果，再处理被除数为零、除数为一、有符号除数为负一、被除数绝对值小于除数。普通输入继续使用原 32 轮迭代。除数为一直接取原始被除数；有符号负一只求一次负值，避免绝对值后再次求负的组合链。

候选已经通过两种存储参数的静态编译。纯 Python 数学检查中，158 个边界早退样例和 99,728 个固定种子随机早退样例与 RV32 商余数模型一致。这只检查数学公式，不验证 RTL 的时序行为或流水线握手。

01 与上一版通用乘法候选的映射 LUT、setup 和 fast hold 相同。该比较仅覆盖这些已取得的工具数值，不能据此推断 DDR 时序或实板分数。

资源口径已核对：`mapped_resources` 来自 DMR，`synthesis_resources` 来自 SNR，`post_route_resources` 来自 PRR 顶层 `Hfpga_soc` 行。布局布线会优化和复制逻辑，映射 LUT 不能当作最终 LUT。

02 在映射阶段比 01 增加 46 LUT，约 1.00%；最终 PRR LUT 为 4615，比 01 少 19。另使用 16 个 Distributed RAM 单元，APM 和 DRM 未增加。这是两次实际工具实现的结果，不能单独把最终差值归因于 RAS 的逻辑结构成本。按最终 LUT 对比，CoreMark/LUT 的盈亏条件为 `T02/T01 < 4634/4615 ≈ 1.00412`。

03 在映射阶段比 02 增加 104 LUT；最终 PRR 比 02 增加 139 LUT，比 01 合计增加 120 LUT，约 2.59%。综合寄存器数量与 02 相同，锁存器为零；最终 PRR 寄存器数量为 4364（02 为 4365）。APM、DRM 未增加。是否值得保留这些面积开销，需要实板总 ticks；按最终 LUT，03 对 01 的 CoreMark/LUT 盈亏条件为 `T03/T01 < 4634/4754 ≈ 0.97476`。此前 3.27% 是映射阶段的增幅，不是最终增幅。

Full DDR 已在三个 BRAM 时序检查通过后放行。此前 Tcl 等待点实际阻塞了整个 Full DDR 流程，未做到预期的综合并行；该轮 `elapsed_seconds` 会包含等待时间，具体工具阶段耗时以各阶段日志为准。

Full DDR 综合已通过：45496 LUT、47887 个寄存器、0 锁存器。与上一版 Full DDR 通用乘法候选比较，207 份非 CPU RTL、初始化文件及约束内容一致；综合资源从 45050 LUT / 47825 个寄存器增加到上述数值，分别增加 446 LUT / 62 个寄存器。APM 均为 69，等效 DRM 均为 35（24 个 DRM36K 加 22 个 DRM18K），没有增加这两类资源用量。对照数据保存在该轮的 `non_cpu_baseline_comparison.json`。

04 综合 CPU setup 估计为 -2.061 ns，综合最差路径从 DCache Tagv RAM 经 MEM/EX 前递、ID 分支判断到 ICache 状态机取消控制。04 正式布线后 CPU setup 为 -1.134 ns，实际最差终点转到 IFU 指令载荷寄存器的同步清零端；两种报告不能混为一条路径。

05/06 将 ICache 取消通知打一拍，同时屏蔽取消周期的请求及 ready；DDR IFU 不再让当拍 flush 直接门控旧预测请求，ICache 则在取消周期禁止新的 AXI 读，避免被取消的 lookup/uncached 请求产生总线副作用。已经受理的读仍按原状态机排空。控制流解析和前递策略保持两种存储配置一致。

05/06 还移除了 IFU 冲刷时对部分无效 PC/预测载荷的写入，但留下了指令 NOP 清零。06 的 CPU 余量改善到 -0.504 ns，TNS 从 -542.506 ns 降到 -53.375 ns，仍未闭合。实际最差路径为 DCache Tagv RAM → MEM 数据 → EX ALU → ID PC 比较 → IFU `if_ins_reg/RS`，19 级逻辑。后续继续清理无效交付载荷对 flush 的依赖，valid 和事务状态仍保持冲刷优先。

06 的 DDR core setup 另为 -3.344 ns，报告还含 DDR PHY reset recovery 违例。这些单独记录，不能将 CPU 时序通过替代全系统通过。04/06 的位流只作为未通过时序的历史产物，不作为 DDR 可用候选。

## 07/08：有效位与交付载荷解耦

06 的最差终点仍为 IF 指令载荷的同步清零端。因此继续将 IF/Skid 的 PC、指令和预测 PC 放到独立时序块：reset 初值保留，正常数据移动和响应捕获按原条件及优先级执行，不再依赖 flush。控制块中的 valid、pending、请求 PC、forced redirect 和 flush 优先级不变。

ID 同样保留 `id_valid` 的冲刷优先级，但接收 IF 载荷时不再把 flush 接入宽寄存器使能。在冲刷沿写入的旧载荷被 valid=0 遮住；下一次有效交付会同时覆盖全部载荷字段。此改动同时用于 BRAM 和 DDR。无效周期的 debug PC/指令可能保留旧值，观察时需结合 valid。

已通过 Htop 两种存储参数的静态编译与差异检查。07 已完成全流程并满足全部约束：最终 4590 LUT / 4371 个寄存器 / 4 APM / 12 DRM，setup +0.829 ns、fast hold +0.145 ns。相比 01，本次工具实现的最终 LUT 少 44；不能将该差值或旧跑分当成已测得的性能收益。

08 布线后 CPU setup -0.729 ns、TNS -98.031 ns，fast hold +0.117 ns，CPU 仍未通过。最差终点转到 BTB `direction[15][0/1]/CE`，路径经过 DCache 数据、EX ALU 和条件分支结果。DDR core setup 另为 -2.756 ns，单独保留在完整报告中。

## 09/10：BTB 方向更新与无效载荷复位

针对 08 的实际方向计数器使能路径，保持训练时机不变，固定展开 16 个表项；每项只用 `update_valid` 和索引决定写使能，饱和计数用显式布尔下一状态写回。命中条件分支转移仍为：taken 时 00→01→10→11→11，not-taken 时 11→10→01→00→00；新建/替换条件分支仍从弱状态开始，无条件跳转仍为 11。

标签与目标载荷不再执行全表复位；valid、方向和类型控制状态仍复位，reset 期间不接收更新。有效位屏蔽未初始化或旧载荷，新条目更新同时写入标签和目标再置 valid。该改动有利于减少复位 FF/动态读写选择开销；是否推断 Distributed RAM 以综合结果为准。容量仍为 16 项，没有新增训练流水拍。

09 BRAM 和 10 Full DDR 已启动独立快照验证。JALR 逆运算比较仅保留在忽略目录内作为未采用的备用候选；当前实际瓶颈是条件分支到 BTB 方向使能，不据此扩大正式改动。

09 已完成并满足全部约束：综合 4490 LUT / 3849 个寄存器 / 0 锁存器，最终 PRR 为 4494 LUT / 3849 个寄存器 / 45 Distributed RAM / 4 APM / 12 DRM。BTB 层级综合资源为 325 LUT / 496 FF / 29 Distributed RAM，证明本轮确有存储推断；相对 07，综合寄存器少 512 个。最终资源对照仍以表中的 PRR 为准。

09 相比 01 的最终 LUT 少 140，约 3.02%；这仅是工具实现的资源结果，未据此声称 CoreMark 分数已经提高。

10 已完成正式时序计算：CPU setup -0.608 ns、TNS -111.052 ns，fast hold +0.100 ns；DDR core setup 另为 -3.236 ns。CPU 最差终点为 IFU `fetch_pc_reg[5]/CE`，Full DDR CPU 70 MHz 仍未闭合。不能将当前 main 工作区声明为已完成双配置时序验收。
