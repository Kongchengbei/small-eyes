# BTB 索引静态审计

日期：2026-10-25

## 地址与审计范围

BRAM profile 的复位 PC 使用 `IRAM_BASE`，其地址为 `0x80000000`。冻结映像 `test/coremark_local.dat` 共 8192 个 32 位词（32768 字节），按该基址形成静态地址序列。当前 BTB 为 16 项直接映射，索引 `PC[5:2]`，tag `PC[31:6]`。

使用 `build/cpu_batch_20261025/btb_audit/audit_btb_indices.py` 对整个 DAT 做 RV32I B/J/JALR 静态语法解码。结果为 851 个 B 类词、567 个 JAL 词、107 个 JALR 词，共 1525 个静态候选 PC。映像里含数据、常量和可能不可达的代码；这些字节可能恰好解码成控制流指令，因此统计不等于真实可执行分支集合。

## 索引对比

| 16 项索引函数 | 非空 bucket | 静态同 bucket PC 对数 | 冲突 bucket 中额外静态 PC 数 |
| --- | ---: | ---: | ---: |
| `PC[5:2]` | 16 | 72,521 | 1,509 |
| `PC[5:2] XOR PC[9:6]` | 16 | 72,352 | 1,509 |
| 再 XOR `PC[13:10]` | 16 | 72,429 | 1,509 |
| 再 XOR `PC[17:14]` | 16 | 72,844 | 1,509 |

按当前静态候选集合，简单 XOR hash 的最佳结果只比直接索引少 169 对，约 0.23%；各方案仍有 16 个非空 bucket，且冲突 bucket 中额外候选 PC 数相同。静态候选远超 16 项只能说明映像内候选地址分散后会填满这些 bucket，不能说明实际执行期间哪些地址同时活跃或互相替换。

## 结论与后续

- 保持 16 项，不扩到 32 项。
- 暂不采用 XOR hash；现有静态证据不足以支持其动态收益，也没有动态冲突计数或 CoreMark 预测性能数据。
- 不据此声称提速、命中率改善或减少了冲刷。
- 后续控制流优化可评估 RAS，另行取得合法动态统计/实测结果后再考虑 BTB 索引变化。

## 本次 RTL 元数据接口变更

`cpu/Btb.v` 增加 `update_is_return` 输入、`lookup_is_return` 输出和每项一位 `is_return` 元数据。复位时清零、有效更新时写入；查找输出由 `lookup_match`（有效项且 tag 匹配）门控。本次未改变索引、表容量、tag、target、方向计数器或 `lookup_hit` 语义；BTB 内部没有 RAS 依赖。

本次没有运行 testbench 或实板测量。接入后的 BRAM 候选已经通过 PDS 编译、综合、映射、布局布线与时序检查；逐轮产物状态见 [02 RAS 运行记录](02_ras_bram.md)。该 PDS 结果不代表实板功能或性能已验证。
