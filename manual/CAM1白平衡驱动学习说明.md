# CAM1 白平衡驱动学习说明

白平衡用来修正光源造成的偏色，让真实的白色或灰色物体在图像中保持中性。
曝光控制总亮度，白平衡调整红、绿、蓝通道的相对增益；二者需要分别设置。
真实绿色物体占画面多数，并不代表白平衡异常，评估时应观察白纸或灰色物体。

## 1. 驱动在工程中的位置

入口程序调用 `cam_configure_vga()`，该函数在 `bsp/camera_stereo_app/camera_stereo.c`
中实现。普通 stereo、诊断、单帧导出三个入口都会调用它；驱动文件自身没有
`main()`，由相应入口负责启动。

一次白平衡设置的调用过程是：

```text
main / main_diag / main_frame_dump
  → cam_configure_vga
    → 公共 OV5640 初始化表（含 0x5180..0x519E 的 AWB 参数）
    → CAM1 自动曝光和白平衡控制
      → cam_read_reg / write_retry → cam_write_reg
        → CPU 写 FPGA 的 CAM1 SCCB GPIO 控制寄存器
          → SCL/SDA 上的 SCCB 通信
            → OV5640 摄像头内部寄存器
```

`0x3406`、`0x5001` 等是摄像头寄存器号。CAM1 的 `0x40000300` 则是 FPGA
控制窗口的基地址，两者不是同一个地址空间。CPU 不会对 `0x3406` 直接进行
内存写入：`cam_write_reg()` 把它拆成高字节 `0x34` 和低字节 `0x06`，连同
数据经 SCCB 发送。本工程软件发送的写设备地址字节是 `0x78`，读地址字节是
`0x79`，对应摄像头的七位地址 `0x3C`。

## 2. 自动模式需要哪些控制

| 摄像头寄存器 | 控制位 | 自动模式设置 |
|---|---|---|
| `0x3406` | bit0，手动白平衡使能 | 0，让摄像头自动调整 RGB 增益 |
| `0x5001` | bit0，AWB 使能 | 1，开启白平衡处理 |
| `0x5001` | bit1，颜色矩阵使能 | 1，保留颜色矩阵处理 |
| `0x5196` | bit5，AWB 冻结 | 0，允许白平衡继续更新 |
| `0x5196` | bit1 / bit0，快速更新 / AWB bias stat | 使用共享表已有的 1 / 1 |

`0x5183` bit7 决定 simple/advanced AWB，共享表写 `0x14`，bit7=0，使用
advanced AWB。共享表已包含完整的 AWB 参数块，本次沿用它，不重写内部算法。
数据手册对部分 advanced AWB 参数没有公开完整定义，不能把未知参数任意
当成“红色加多少、绿色减多少”的旋钮。

`cam1_awb_regs` 每项的三个字段分别是寄存器号、目标位值、位掩码。例如：

```c
{0x3406u, 0x00u, 0x01u}, /* 只清除 bit0 */
{0x5001u, 0x03u, 0x03u}, /* 只设置 bit1、bit0 */
{0x5196u, 0x03u, 0x23u}  /* 清 bit5，置 bit1、bit0 */
```

## 3. 为什么使用读-改-写

一个寄存器可能同时管理多个功能。为了只修改需要的位，先读取旧值，计算
新值，再写回：

```c
value = (uint8_t)((value & ~mask) | (expected & mask));
```

`value & ~mask` 保留掩码之外的原有位，`expected & mask` 放入需要修改的位。
例如旧 `0x5001=0xA0`、掩码 `0x03`、目标 `0x03`，计算结果为 `0xA3`。
其余功能位保持原值。白平衡的自动模式不是单纯往一个寄存器写 `0x00`。

实际代码对每次写入最多重试三次，然后读回并核验：

```c
(value & mask) == (expected & mask)
```

写成功只表示通信收到应答；读回匹配才能进一步确认控制位设置生效。
通信失败或不匹配会把寄存器号写入 `failed` 并返回 `false`，上层不再开启
该路采集。设置成功仍不代表图像颜色已经正常，需要采集验证。

## 4. 谁计算红、绿、蓝增益

自动模式由 OV5640 内部算法分析场景并更新增益，CPU 无需逐帧读取 RGB565
图像计算白平衡。软件负责初始化、模式设置、状态读取和错误处理。

实际自动增益读取下面六个只读寄存器：

| 通道 | 高位寄存器 | 低位寄存器 | 组合方式 |
|---|---|---|---|
| R | `0x519F` | `0x51A0` | `((high & 0x0F) << 8) | low` |
| G | `0x51A1` | `0x51A2` | 同上 |
| B | `0x51A3` | `0x51A4` | 同上 |

高字节仅低四位有效，所以每个增益为十二位。单帧导出程序中的
`report_sensor_stats()` 已按此方式读取和拼接，并打印 `CAM1_AWB_CURRENT`。
增益值表示通道放大设置，不是这一帧平均红绿蓝强度，也不是旋转角度。
寄存器是顺序读取，未锁存在同一帧或同一时刻，不能当成严格对应导出帧的金样。

单帧导出在配置后等待一秒，让摄像头有时间自动调节，再开启 FPGA 采集。
这段等待利用本工程 CPU 的 `0xB03` 时间计数 CSR；必须先设置 `0xB88` bit2
使能计数器，否则等待可能不结束。一秒是预留时间，不是自动收敛检测。

## 5. 如果以后改为手动白平衡

手动模式将 `0x3406` bit0 置一，再为三个通道写固定增益：

| 通道 | 高四位 | 低八位 |
|---|---|---|
| R | `0x3400` | `0x3401` |
| G | `0x3402` | `0x3403` |
| B | `0x3404` | `0x3405` |

例如将十二位数 `0x0540` 拆成高四位 `0x05` 和低八位 `0x40`。这里仅演示
数据格式，该值不是为本板标定的红色增益，也不是本次固件采用的设置。
高位寄存器应保留无关位，写入后读回核验。在线修改多个通道时，可参考厂家
应用指南的 `0x3212` group 3 流程，先 `0x03` 开始组、写各参数、`0x13`
结束组、`0xA3` 提交组，以协调多寄存器更新；任一步通信失败都应中止并报告。

固定 RGB 增益需要在确定光源下用中性物体标定，换光源后可能再次偏色。
目前固件使用自动模式，没有加入未经标定的手动增益。

## 6. 本次能确认什么

软件实现了自动模式的明确配置、读回检查、单帧导出的启动等待和实际增益
日志，并保留 CAM1 EV +1 自动曝光设置。尚未上板验证。
如果新图像仍只有少数绿色像素值，而红、蓝几乎始终为零，原因可能涉及
数据采样或格式；自动白平衡不能保证恢复已经丢失的数据。需观察新的图像、
实际增益和曝光统计，再决定是否进行手动标定或继续检查采集链路。

§7.4，以及 `OV5640_AF_Imaging_Module_Application_Guide_(DVP_Interface).pdf`
§4.9.5。曝光 EV +1 预设来自后者 §4.9.4。
