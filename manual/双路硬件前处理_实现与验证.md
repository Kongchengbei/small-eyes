# 双路自主硬件前处理：第一版实现与验证

日期：2026-10-02。用户确认双目已稳定后，授权实现前处理。
这里只处理摄像头原图，不增加 VGA/HDMI 显示；640×480 是原图尺寸。

## 实现范围

每路各有一套控制器、颜色筛选、候选框和裁剪缩放硬件，只有 DDR 接口仲裁共用。

```text
CAM1 DVP → FIFO → Camera DMA → CAM1 原图双槽 → 前处理1 → ROI bank1双槽 ┐
                                                                    ├→ 未来 NPU
CAM2 DVP → FIFO → Camera DMA → CAM2 原图双槽 → 前处理2 → ROI bank2双槽 ┘
```

前处理控制器自身包括读 DDR、扫描、筛选、裁剪/缩放和写 DDR 状态机。
CPU 仍负责启动时摄像头初始化，但不需要逐帧启动、选择摄像头或释放原图。
读写功能集成在控制器中，不需要另挂一个软件调度的通用 DMA。

| 文件 | 作用 |
|---|---|
| `soc/Hpreprocess_color.v` | RGB565 颜色判定 |
| `soc/Hpreprocess_regions.v` | 有界同色包围框增长/合并 |
| `soc/Hcamera_preprocess.v` | 单路原图领取、扫描、候选粗筛、ROI 最近邻缩放、DDR 读写、归还 |
| `soc/Hpreprocess_stereo.v` | 实例化两套控制器和 DDR 仲裁 |
| `soc/Hcamera_subsystem.v` | 新增原图完成槽/token及硬件归还接口 |
| `soc/Hfpga_soc.v` | 可选接入现有双目和共享 DDR |
| `sim/tb_preprocess_stereo.sv` | 双路数据、所有权、故障及 Camera 连接仿真 |

## 算法与第一版限制

RGB565 扩展成 RGB888 后比较可配置阈值，不经过模型。
红色要求 R 足够亮且大于 G/B；黄色要求 R/G 足够亮且大于 B；蓝色对应 B 优势；
黑色要求三个通道都低于上限。颜色编码为 0=非候选、1=红、2=黄、3=蓝、4=黑，
冲突优先级红→黄→蓝→黑。加法比较使用九位，避免阈值溢出。

候选生成是**同色包围框的外扩一像素增长/合并**，不是精确连通域标记。
一个像素同时命中多个同色框时合并这些框；允许最多8个临时候选。
随后依据颜色像素数、框面积、颜色占比和长宽比过滤，再按 margin 外扩并裁至原图边界。
候选容量溢出时丢弃整次前处理任务，不发布不完整结果。

这版尚无形态学去噪、精确连通域、多尺度检索和真实路标数据验证。
小噪点也会占用临时候选槽，可能导致整帧被丢弃；包围框增长可能合并无关同色区域。
颜色候选不等于路标类别，也不保证真实场景召回率。黑色默认关闭，可单独开启，
避免把大量暗背景当成候选；后续可作为候选内部的辅助特征。

输出为逐行连续、little-endian RGB565 小图；每个 ROI 单独占一个32KiB stride。
坐标包含两个端点，描述符每框打包为 `{y1,x1,y0,x0}`，每个坐标16位。
最近邻采样采用 `src=x0+floor(dst*ROI_size/output_size)` 的整数 DDA，
不用可变除法器；直接拉伸到输出尺寸，**尚未实现等比例 letterbox**。
末尾不足一个256位 beat 的写入按 WSTRB 精确保护未使用字节。

两路模块配置接口独立，领取原图时锁存配置；修改配置不会影响正在处理的帧。
输出宽高可配置，第一版上限128×128，顶层示例96×96。
示例阈值、8候选上限及96×96都不是已冻结的模型协议；顶层目前连接常量，
尚未增加 CPU 可写的前处理 MMIO 配置窗口。
RGB888/INT8、归一化、通道排列和量化参数待模型确定后补充，不虚构 NPU 算子或指令集。

## 原图和 ROI 的所有权

1. Camera DMA 成功写完原图后，将对应槽设为 READY。
2. Camera 硬件接口先锁存该槽帧 token，再允许前处理领取，避免新 READY 配旧帧号。
3. 前处理仅在有空闲 ROI bank 且没有未交付描述符时领取原图。两个原图槽同时 READY 时先槽0。
4. 原图扫描和所有 ROI 回读过程中不释放原图；所有 ROI 写响应成功后才发布描述符并归还原图。
5. 下游 `result_valid && result_ready` 表示取得描述符，不等于可以覆盖 ROI。
6. 下游在最后一次读取 ROI 完成后，用 `roi_release_valid + bank + frame token` 归还。
   未取得描述符的提前归还、错误/过期 token 均拒绝并计数。
7. 两个 ROI bank 都被下游持有时不继续读取原图，不覆盖在用数据；Camera 原图槽耗尽后按已有策略丢新帧。

`HARDWARE_CONSUMER=1` 时 Camera 原图释放只听硬件消费者，忽略 CPU 的
`CAM_BUFFER_RELEASE` 写入，避免旧调试程序提前释放。默认0保持旧软件消费者模式。

空候选帧直接归还原图并计数，不产生 ROI 描述符。
AXI 读/写错误、配置错误或候选容量溢出时不发布结果。
AXI 超时会报错，但保持有效请求与载荷并等待事务排空，不能在 DDR 事务未完成时强制释放原图。
错误码：1=配置，2=读，3=写，4=等待超时，5=候选容量溢出。

## DDR 分区记录

既有 NPU input 预留区仍为 `[0xB8000000,0xB9000000)`，共16MiB。

| 用途 | bank/slot 起始地址 | 每块预留 |
|---|---|---|
| CAM1 原图 | `0xB8000000`、`0xB8100000` | 1MiB |
| CAM2 原图 | `0xB8200000`、`0xB8300000` | 1MiB |
| CAM1 ROI | `0xB8400000`、`0xB8500000` | 1MiB |
| CAM2 ROI | `0xB8600000`、`0xB8700000` | 1MiB |
| 未分配 input | `[0xB8800000,0xB9000000)` | 共8MiB |

四个原图槽保持不变；每帧640×480 RGB565实际614400字节。
新增四个 ROI bank 共占4MiB，独立于原图，不能把 bank 当成一张完整原图。
每个 ROI bank 默认最多8张小图，每张偏移为 `roi_index*32768`，
最大128×128 RGB565恰好32768字节；实际有效长度随输出尺寸变化。
bank 的剩余空间未自动分配。权重、输出及 scratch 分区不变。

## 顶层开关与当前可运行边界

`Hfpga_soc.PREPROCESS_ENABLE` **默认0**：保持已验证双目软件消费路径，绕过新仲裁层。
置1才启用两套前处理并切换为硬件原图消费者；不是烧录一个新 CPU bin 就能添加的功能，
需要重新生成 FPGA 位流。四个新 RTL 文件已经加入 `project/project.pds` 源文件列表。

当前没有 NPU，顶层暂将结果 `ready` 和 ROI 归还拉低。
因此启用后每路第一份非空 ROI 描述符会等待下游，后续不能持续消费原图。
这是接口占位，**不是完整 AI 链路，也不能直接把此模式当成持续吞吐固件**。
仿真中的测试消费者会检查图像后归还，仅用于验证协议，不能等同真实 NPU 已实现。
尚无1～5FPS硬件选帧节流，控制器在数据/空间可用时自主执行。

## 离线验证命令

```sh
make preprocess-lint
make preprocess-color-test
make preprocess-test
make preprocess-camera-test
make preprocess-640x480-test
make addr-map
make camera-board-lint
make camera-board-lint BOARD_LINT_EXTRA=-GPREPROCESS_ENABLE=1
make camera-snapshot-test camera-stereo-test
```

`preprocess-test`：双路独立不同颜色图案、逐像素 golden 裁剪缩放、帧内配置锁存、
margin外扩和边界饱和裁剪、末拍字节保护、描述符背压、双 bank 不覆盖、提前/过期归还拒绝、空帧、
非法尺寸、读/写故障、AXI 超时排空及候选容量溢出。

`preprocess-color-test`：红/黄/蓝/黑基础颜色、灰/白/绿非候选、颜色开关、九位阈值比较。

`preprocess-camera-test`：连接两个真实 Camera RTL 实例，独立 PCLK，通过
DVP→FIFO→Camera DMA→共享 DDR→两套前处理→ROI DDR，检查三轮不同帧 token。
测试消费者仅接 ROI，不负责 Camera 原图释放；CPU 意外释放原图必须被拒绝。

`preprocess-640x480-test`：两路完整640×480原图扫描，分别1/2个小区域，
输出96×96，每个 ROI 与独立整数除法 golden 逐像素比较。
一次带等待的仿真测得 CAM1 406298周期、CAM2 429343周期；按70MHz仅折算为
约5.8/6.1ms，**不是实板时序或67ms最坏时间保证**。大片/多候选、DDR实际等待、
NPU竞争及布局布线后的频率均需另验；不能由此直接承诺真实路标吞吐。

本轮离线执行结果：

```text

PREPROCESS_STEREO ALL PASS（含边界裁剪、所有权与故障注入）
PREPROCESS_CAMERA PASS（两路 Camera RTL，各三帧，无 CPU 原图释放）
RAW 640x480 SIM：两路所有 ROI 像素比较通过
SOC_ADDR_MAP_PASS
CAMERA_SNAPSHOT_OVERFLOW_RECOVERY_PASS
CAMERA_STEREO_PASS
前处理 lint、顶层默认/启用前处理两种 lint：通过

```
