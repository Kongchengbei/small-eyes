# 视频流图标识别任务实施计划

## 1. 任务目标

在盘古 200Pro+（PG2L200H-6IFBB676）平台上实现视频流中的图标识别：

1. FPGA 接收摄像头视频流，并保持视频采集或显示链路连续工作。
2. 按设定间隔抽取视频帧，对目标区域进行裁剪、缩放和像素格式转换。
3. 将输入图像写入 DDR3 的 NPU 输入区。
4. 使用 INT8 小型卷积神经网络完成图标分类。
5. 输出类别编号、置信度和有效标志，并保持结果直到下一次推理完成。
6. FPGA 位流、CPU 程序和模型权重由 PDS 写入板载 QSPI Flash；上电后由 FPGA 内部启动逻辑将 CPU 程序和权重搬入 DDR3。

本任务不要求很高的 AI 推理帧率。建议第一版目标为每秒识别 1～5 帧，视频显示链路不因推理降帧而停止。

## 2. 首先需要冻结的需求

开始设计计算阵列前必须确定以下内容：

- [ ] 图标类别列表、类别编号和类别总数。
- [ ] 无图标时的输出定义，并增加 `background/unknown` 类。
- [ ] 画面中是否只出现一个图标。
- [ ] 图标位置是否基本固定，能否使用固定 ROI。
- [ ] 是否需要输出目标框，还是只输出类别和置信度。
- [ ] 摄像头型号、输入分辨率、帧率和像素格式。
- [ ] 是否需要同时显示原始视频和识别结果。
- [ ] 可接受的最低准确率、最大推理延迟和最低识别帧率。

推荐第一版将任务限定为：单个图标、固定或可预先确定的 ROI、只做分类。若图标位置任意且同时可能出现多个目标，则任务将升级为目标检测，需要重新评估模型与硬件规模。

## 3. 推荐系统数据流

```text
摄像头视频流
    ├──> 原视频显示/传输链路
    │
    └──> 每隔 N 帧抽取一帧
             │
             v
        ROI 裁剪与缩放
             │
             v
       灰度化或 RGB 转换
             │
             v
      DDR NPU 输入缓冲区
             │
             v
         INT8 CNN 推理
             │
             v
       类别、分数、有效标志
             │
             v
        CPU 读取或画面叠加
```

视频链路与 AI 推理解耦。推理模块处理上一张抽取帧时，视频链路仍可继续运行；识别结果在下一次推理完成前保持不变。

## 4. 第一版模型建议

第一版采用规则、易于硬件实现的小型 CNN，避免引入复杂算子：

```text
输入：96×96×1，INT8

Conv 3×3, stride 2,  1 -> 8   + ReLU
Conv 3×3, stride 2,  8 -> 16  + ReLU
Conv 3×3, stride 2, 16 -> 32  + ReLU
Conv 3×3, stride 2, 32 -> 64  + ReLU
Global Average Pooling
Fully Connected：64 -> 类别数
输出 logits，由 CPU 完成最大值和置信度处理
```

初步估算：

- 每帧约 2～3 百万次 MAC。
- INT8 权重约数十 KiB，具体取决于类别数和最终通道数。
- 96×96 灰度输入为 9216 Byte。
- 最大中间特征图约数十 KiB。
- INT8 输入和权重，INT32 累加；每层使用固定的量化 scale/shift。

若颜色是区分类别的重要特征，可以改为 `96×96×3` RGB 输入。若颜色不重要，优先使用灰度输入以减少带宽和运算量。

模型结构必须与 NPU 支持的算子共同冻结。计算阵列尚未确定前，不应先训练依赖复杂算子的最终网络。

## 5. 数据集任务

### 5.1 数据采集

- [ ] 每类采集至少 300～1000 张有效图片。
- [ ] 覆盖不同距离、角度、比例、光照和背景。
- [ ] 包含旋转、轻微遮挡、运动模糊和摄像头噪声。
- [ ] 收集无目标、相似物体和错误图标作为 `background/unknown`。
- [ ] 保存原始视频，训练图片由脚本统一抽帧和裁剪。

### 5.2 数据集划分

训练集、验证集和测试集应按不同拍摄视频或不同拍摄批次划分，不能把同一段视频的相邻帧随机分散到不同集合，否则测试准确率会虚高。

建议比例：

```text
训练集：70%
验证集：15%
测试集：15%
```

### 5.3 数据集交付物

- [ ] 类别编号文件 `labels.txt`。
- [ ] 数据集版本说明。
- [ ] 训练、验证、测试文件清单。
- [ ] 图像预处理参数：ROI、缩放方式、通道顺序、均值和量化规则。

## 6. 模型训练与导出任务

- [ ] 在电脑端完成浮点模型训练并记录基线准确率。
- [ ] 完成 INT8 量化，并比较量化前后的准确率。
- [ ] 固定卷积、激活、池化和全连接的精确计算规则。
- [ ] 固定 padding、舍入、饱和和右移规则。
- [ ] 导出 FPGA 使用的 `model.bin`。
- [ ] 导出至少一组逐层黄金输入和输出。
- [ ] 生成模型清单，记录版本、大小、CRC32 和类别数。

建议的模型二进制结构：

```text
model.bin
├── 文件头：magic、格式版本、层数、类别数、总长度、CRC32
├── 逐层描述符：类型、输入/输出尺寸、kernel、stride、padding、数据偏移
├── INT8 weights
├── INT32 bias
└── 每层 quant scale/shift
```

最终输出至少包括：

```text
model.bin
labels.txt
model_manifest.json
golden/input.bin
golden/layer_XX_output.bin
golden/final_output.bin
```

## 7. Flash 到 DDR 启动任务

详细设计见 [QSPI Flash 到 DDR3 启动搬运方案](QSPI_Flash到DDR启动搬运方案.md)。本任务中的实施顺序为：

- [ ] 生成当前工程的最终 `.sbit` 并记录实际大小。
- [ ] 确认 PDS 配置宽度为 X8，并能识别两颗 Flash。
- [ ] 确认配置后 Flash 管脚释放给用户逻辑，不能长期启用 Persist Pin。
- [ ] 以位流实际末地址为依据，将 `USER_BASE` 向上对齐到安全边界。
- [ ] 先写入并读取 256 Byte 递增测试数据。
- [ ] 实测双 Flash X8 的地址含义、字节交织和高低半字节顺序。
- [ ] 完成固定地址的 Flash 到 DDR 256 Byte 搬运。
- [ ] 加入长度检查、地址边界检查、超时和 CRC32。
- [ ] 搬运最小 CPU 程序并在 CRC 成功后释放 CPU。
- [ ] 最后搬运 `model.bin` 到 `0xB900_0000` 权重区。

Flash 容量预算必须依据最终位流重新计算：

```text
可用用户容量 = 32 MiB - 位流 - CPU 程序 - 对齐/数据头开销
```

不能因为 DDR 权重区预留了 32 MiB，就假设 Flash 一定还能容纳 32 MiB 模型。

## 8. 视频预处理任务

- [ ] 接通摄像头输入并确认像素时序和格式。
- [ ] 明确视频帧开始、行有效和像素有效信号。
- [ ] 实现抽帧控制，第一版目标 1～5 FPS。
- [ ] 实现固定 ROI 裁剪。
- [ ] 实现缩放到 96×96；第一版可使用最近邻缩放。
- [ ] 根据模型需求实现灰度化或 RGB 通道整理。
- [ ] 按模型的零点和比例完成 INT8 输入量化。
- [ ] 使用至少两个输入缓冲区，防止采集和推理同时访问同一帧。
- [ ] 将输入帧写入 `0xB800_0000` 起的 NPU 输入区。

建议先用静态测试图片验证预处理，再接入实时摄像头。

## 9. NPU 硬件任务

当前工程只完成了 NPU 地址规划、控制寄存器、DMA 骨架和独立仲裁器验证，尚无卷积计算阵列，DMA 和仲裁器也尚未接入最终 SoC 顶层。详细状态见 [NPU 第二阶段当前状态](NPU第二阶段当前状态.md)。

### 9.1 现有模块集成

- [ ] 将 `Hnpu_dma` 接入 SoC 顶层。
- [ ] 将 `Haxi_2m1s_arbiter` 接入 DDR AXI 接口。
- [ ] 完成 CPU 时钟域与 DDR/NPU 时钟域的命令、完成和错误握手。
- [ ] 为 NPU 控制器增加软件可读的错误状态。
- [ ] 完成 CPU 写输入、DMA 读取、DMA 写回、CPU 检查的板级闭环测试。

### 9.2 计算阵列

- [ ] 实现 INT8 乘加单元和 INT32 累加。
- [ ] 实现 3×3 卷积数据窗口或等效分块计算结构。
- [ ] 实现 bias、ReLU、量化右移、舍入和饱和。
- [ ] 实现特征图双缓冲或 ping-pong 缓冲。
- [ ] 实现 Global Average Pooling。
- [ ] 实现全连接层，或复用卷积 MAC 阵列。
- [ ] 实现逐层调度器和模型描述符解析。
- [ ] 使用黄金数据逐层比较，定位第一个不一致层。

第一版优先保证结果正确，不以满带宽或最高并行度为目标。通过完整模型后再增加 MAC 并行数、AXI burst 长度和片上复用。

## 10. CPU 软件任务

- [ ] 初始化 UART、DDR 和 NPU 控制寄存器。
- [ ] 等待 Flash 启动搬运完成，并检查启动错误码。
- [ ] 管理输入双缓冲和 NPU 任务提交。
- [ ] 配置输入、权重、输出地址及任务参数。
- [ ] 处理 NPU 完成中断或轮询 `done`。
- [ ] 读取输出 logits，计算最大类别和置信度。
- [ ] 使用 `labels.txt` 对应关系输出类别。
- [ ] 通过 UART 或显示叠加输出识别结果。
- [ ] 对超时、非法模型、CRC 错误和 NPU 计算错误给出明确状态。

## 11. DDR 地址约定

沿用 [NPU 第二阶段地址映射](NPU第二阶段地址映射.md)：

| 地址范围 | 大小 | 用途 |
|---|---:|---|
| `0x8000_0000`～`0xB7FF_FFFF` | 896 MiB | CPU 程序和普通数据 |
| `0xB800_0000`～`0xB8FF_FFFF` | 16 MiB | 输入图像/输入特征图 |
| `0xB900_0000`～`0xBAFF_FFFF` | 32 MiB | INT8 模型权重 |
| `0xBB00_0000`～`0xBBFF_FFFF` | 16 MiB | NPU 输出 |
| `0xBC00_0000`～`0xBFFF_FFFF` | 64 MiB | 中间特征图和临时区 |

视频输入、权重、输出和中间特征图应保持 32 Byte 对齐，以适配当前 256-bit AXI 数据口。

## 12. 分阶段验收标准

### 阶段 A：启动链路

- PDS 能将位流和用户测试数据写入 Flash。
- 上电后能正确读出 256 Byte 递增数据。
- 能将数据搬入指定 DDR 地址并通过 CRC32。
- CRC 成功前 CPU 保持复位，成功后 CPU 正常运行。

### 阶段 B：DDR 与 NPU 数据通路

- CPU 能向非缓存输入区写入测试数据。
- DMA 能通过 256-bit AXI 正确读写 DDR。
- CPU 和 DMA 并发访问不会破坏事务。
- 跨时钟命令、完成和错误状态可靠。

### 阶段 C：单层计算

- 3×3 INT8 卷积与电脑端黄金结果逐元素一致。
- bias、ReLU、量化和饱和边界结果一致。
- 支持连续处理多个输入块且不会覆盖缓冲区。

### 阶段 D：完整静态图片推理

- `model.bin` 能从 Flash 搬入 DDR。
- 单张测试图片所有层输出与黄金数据一致。
- FPGA 最终类别与电脑端量化模型一致。

### 阶段 E：视频流推理

- 视频采集或显示不因低帧率推理而停止。
- 能按设定间隔稳定抽帧并提交推理。
- 类别和置信度能稳定输出或叠加显示。
- 连续运行期间无 DDR 地址越界、死锁或帧缓冲撕裂。
- 达到冻结的准确率、延迟和识别帧率指标。

## 13. 当前优先级

在最终数据集和模型尚未建立时，按以下顺序推进：

1. 确认板卡型号、Flash 型号、摄像头接口和视频格式。
2. 使用假权重和测试数据打通 Flash 到 DDR。
3. 将现有 NPU DMA、仲裁器和跨时钟握手接入顶层。
4. 使用静态图片打通视频预处理到 DDR 输入缓冲区。
5. 同时建立图标类别表和采集数据集。
6. 冻结第一版模型、算子和 INT8 量化规则。
7. 实现并验证卷积计算阵列。
8. 完成静态图片推理后再接实时视频流。

## 14. 暂不纳入第一版的内容

- 多目标检测和复杂目标框回归。
- 高帧率实时推理。
- 动态加载任意神经网络结构。
- FP16/FP32 计算阵列。
- 复杂插值缩放、图像增强和视频编码。
- 在 FPGA 上进行 Softmax 指数运算；第一版可由 CPU 比较 logits 或做近似置信度。

以上功能只有在第一版分类链路稳定、资源与时序仍有余量时再评估。
