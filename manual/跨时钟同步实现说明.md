# 跨时钟同步实现说明

工程里的跨时钟电路由 RTL 的寄存器、时钟沿和握手逻辑直接描述。边沿触发的 `always` 块本身表达了触发器及其数据连线，`ASYNC_REG` 不是这些电路实现功能所必需的。当前 PDS 日志 `project/logbackup/run_2026-10-08-22-03-50.log:1351-1382` 报告 `Sdm-2008`：该属性不合法、没有效果，工具忽略其值。因此 Compile 仍可从 RTL 读取两级寄存器、FIFO 和握手逻辑；这不等于 PDS 识别并验证了 CDC，也不证明同步器寄存器会相邻放置、获得专门时序保护或达到某个亚稳态 MTBF。工程没有改用未经验证的替代属性。

## RTL 中的实际结构

- 摄像头 FIFO 在写域和读域各用两级寄存器同步对方的 Gray 编码指针，再在本域计算 full/empty。像素与帧事件通过双时钟 FIFO 传递，而不是将 PCLK 单拍事件直接接入系统时钟逻辑。见 [Hcamera_async_fifo.v](../soc/Hcamera_async_fifo.v#L28) 的指针寄存器、[两拍复位释放](../soc/Hcamera_async_fifo.v#L74) 和 [指针同步及 FIFO 判断](../soc/Hcamera_async_fifo.v#L95)。
- 摄像头子系统对 CPU、DDR、PCLK 三个域分别异步断言复位并用两拍寄存器同步释放。见 [Hcamera_subsystem.v](../soc/Hcamera_subsystem.v#L65)。
- 子系统中的单比特命令、应答和状态走两级同步寄存器；CPU/DDR 之间的 clear、release 与快照控制使用 toggle 请求/确认。release 的两位 payload 在请求期间保存在源域，目标域先同步 toggle，再采样 payload 并返回应答。PCLK 快照也经请求/应答状态机协调，宽数据在应答前保持稳定。相关逻辑见 [子系统 CDC 信号](../soc/Hcamera_subsystem.v#L86)、[CPU 快照同步寄存器](../soc/Hcamera_subsystem.v#L230)、[DDR 域接收逻辑](../soc/Hcamera_subsystem.v#L417) 及后续 PCLK 快照状态机。
- PCLK 域快照请求在两级同步后触发宽快照捕获，数据保持稳定后翻转应答；CPU 域两级同步应答，再锁存稳定的宽数据。见 [PCLK 请求同步与快照应答](../soc/Hcamera_dvp_rx.v#L41) 和 [CPU 域应答同步及快照锁存](../soc/Hcamera_dvp_regs.v#L27)。
- INT8 控制模块将 enable 和 clear toggle 从 CPU 域同步到 DDR 域，并把 ready、busy、slot、错误等实时状态分两级同步回 CPU。1024 位统计数据不逐位做电平同步：CPU 发起 toggle 请求，DDR 捕获整组统计值并返回应答，CPU 收到应答后锁存整组快照供 MMIO 读取。见 [Hrgb565_int8_regs.v](../soc/Hrgb565_int8_regs.v#L16) 的寄存器、[CPU 域请求与应答](../soc/Hrgb565_int8_regs.v#L43) 和 [DDR 域快照捕获](../soc/Hrgb565_int8_regs.v#L81)。

这些结构说明了 RTL 如何传递跨域事件和数据，不构成完整 CDC 签核结论。当前约束文件明确列出的异步时钟组见 [soc.fdc](../soc.fdc#L29)；该约束声明本身也不证明所有路径都已完成 CDC 检查或布线审查。
