## 第一批：模型头校验拆拍与 INT8 容量计数

soc/Hnpu_cnn_engine.v：校验分为 MAGIC/VERSION、FORMAT、H×W 暂存、低 16 位 H×W 再乘 C 并比较 SHAPE。相对原路径多 3 拍，仅在模型未缓存的加载检查路径使用；缓存命中和 MAC 主循环未改。保留原截断、错误优先级、成功初始化和 busy/done 语义。模型头在这些状态中保持不变。

soc/Hrgb565_int8_lane.v：以寄存器精确维护可分配数量，替代 56 槽组合 popcount 与加法树。复位为 56；实际逐槽预留减 1；归还/清理的非空到空转换加 1；全局 epoch 到 FFFFFFFF 的同拍归零并保持不可分配。desc_ready 仍要求整批所需空间，活动批次不接受另一批，原分配扫描与地址映射不变。

主代理发现并要求修复了第一稿重复归还可重复增加容量的问题。修正版根据写回时目标状态计数，release/clean 同槽去重，分配最后写入的优先级保持不变。合法分配掩码来自空闲状态快照，本通道只有一个分配者，活动分配期间其他事件只能释放已有槽，因此每次预留目标仍为空。generation 初始化为 0，分配只写 epoch 1..FFFFFFFE，epoch 在到 FFFFFFFF 时永久停止接新批，故未新增动态宽代次读取。

审查覆盖：连续重复/过期归还、归还与清理并发、归还与分配并发、清理回滚、满缓存与空描述符、非法描述符、enable/clear_errors、epoch 饱和及 used/peak 原有一拍统计时序。以上为代码审查，不是仿真证明。

完整 Full DDR SoC 通过 Icarus 静态编译和 Verilator --lint-only。现有警告仍有 3 个 IMPLICIT、41 个 WIDTHTRUNC、2 个 WIDTHCONCAT、85 个 WIDTHEXPAND、6 个 CASEINCOMPLETE、8 个函数中间变量 LATCH；无 UNOPTFLAT 或 MULTIDRIVEN。不宣称零警告。CPU、SoC 顶层、配置、项目文件和时序约束哈希均未改变。日志在 build/ddr_wns_20261031/batch01/。

## 第四批：沿地址和统计路径优化

2026-11-01，Luna high 完成局部修改，主代理检查实际差异：

1. 模型权重地址：每层从描述符初始化 32 位 weight_base。FC 产生非末 logit 后加输入通道数；CONV 完成一个输出通道的全部空间位置后加 kernel_size。MAC 读地址只需基址加索引，bias 地址不变。旧乘法函数第二个参数为16位；最终模型读地址也是16位，因此基址滚动加法在可见地址的模65536意义下等价，未依赖上位乘积一致。
2. 张量读地址：去掉 CONV/POOL 中由坐标边界控制的地址选择器，保留原 tensor_valid_q 判定。当前配置 RAM 为16384字节；padding 的无效内部预取可能超数组范围，其返回值不会被消费。有效坐标的地址、valid 同步关系、MAC/POOL 终止和 prime/flush 序列不变，不增加外部访问或主循环周期。
3. 公共层校验：在已有元数据阶段分别登记尺寸、容量和描述符合法位，ST_CHECK 保留 unsupported→common shape→quant→算子专用 shape 的报错顺序。后续每次进入 ST_CHECK 前均重新登记，无新增主循环周期。
4. 非法归还计数：将当前非法事件登记为1位 pending，基础计数提交前一拍事件，组合输出投影当前 pending。若旧输出为 C，则下一拍 base'=C、pending'=当前事件 E，输出为 E?sat_inc(C):C，与原32位饱和计数逐拍相同。连续事件、全1饱和、复位和 clear_errors 保持原行为；真正归还匹配、槽状态、容量计数和代次未变。

CPU、配置、顶层、模型和固件没有本轮修改。已采纳的 FDC 保持不变。静态检查及 PDS 结果另记，不以代码审查替代实板功能验证。


第四批综合后补充核验：8 个 tensor_a/b_0..3 的实际 RAM 读口 ADDRB 均只接 tensor_read_addr[13:0]，WEB 固定0，故当前16384字节容量的内部地址范围完整且无写副作用。padding 无效预取返回的数据仍由同拍配对的 valid_q 屏蔽。证据在 batch04/ram_mapping.json、ram_mapping.txt 和 review.md；这是静态网表核查，不是板上功能验证。
