# 整体目标

最终你希望得到的是：

```
                    你的 small-eyes SoC
┌──────────────────────────────────────────────┐
│                                              │
│   RISC-V CPU                                 │
│      │                                       │
│      ├── UART → MobaXterm                    │
│      │                                       │
│      ├── Camera MMIO                         │
│      │       │                               │
│      │       ├── 摄像头状态                  │
│      │       ├── 帧计数                      │
│      │       ├── 像素计数                    │
│      │       └── 错误状态                    │
│      │                                       │
│      └── SCCB/I²C配置 OV5640                 │
│                                              │
│ Camera0 ─DVP→ DVP RX0 ─┐                     │
│                         ├→ FIFO/DMA → DDR    │
│ Camera1 ─DVP→ DVP RX1 ─┘                     │
│                                      │       │
│                                      ↓       │
│                                     NPU      │
└──────────────────────────────────────────────┘
```

这里其实有两层“摄像头驱动”：

```
软件驱动
CPU C代码
负责：
OV5640配置
读取状态
UART打印
控制采集

+

硬件驱动
FPGA Verilog
负责：
DVP接收
像素拼接
FIFO
帧统计
DDR/DMA
```

这两部分合起来，才是你这个 SoC 里的完整 Camera Driver。

# 第五阶段：专门做 Camera Debug Registers

这是我特别建议你加的。

不要让 CPU直接去“猜”DVP有没有工作。

给摄像头做 MMIO，比如：

```
0x40000300 CAMERA0_CTRL
0x40000304 CAMERA0_STATUS
0x40000308 CAMERA0_FRAME_CNT
0x4000030C CAMERA0_PIXEL_CNT
0x40000310 CAMERA0_PCLK_CNT
0x40000314 CAMERA0_ERROR
```

例如：

### STATUS

```
bit 0 : camera enabled
bit 1 : PCLK detected
bit 2 : VSYNC detected
bit 3 : HREF detected
bit 4 : frame received
bit 5 : FIFO overflow
```

CPU只需要：

```
status = CAMERA0_STATUS;

uart_puts("CAM0 STATUS = ");
uart_puthex(status);
```

就能看到：

```
CAM0 STATUS = 0x0000001F
```

# 第六阶段：单摄像头 → FIFO → DDR

到这里才开始碰 DDR。

结构：

```
OV5640
 ↓
DVP Receiver
 ↓
RGB565
 ↓
Async FIFO
 ↓
Camera DMA
 ↓
DDR
```

为什么需要 FIFO？

因为：

```
Camera PCLK
```

和：

```
DDR / SoC clock
```

不是同一个时钟域。

所以：

```
camera clock domain
         ↓
     Async FIFO
         ↓
system/DDR clock domain
```

------

## Camera DMA

这里建议不要直接拿你现在 NPU DMA 硬改。

可以：

```
Hcamera_dma.v
```

第一版做得很简单：

```
frame_start
 ↓
write_addr = CAMERA_FRAME_BASE

每收到一个pixel
 ↓
写DDR
 ↓
地址++
```

例如：

```
CAM0_FRAME_BASE = 0xB8000000
```

以后双目：

```
CAM0 = 0xB8000000
CAM1 = 0xB8100000
```

具体区域以后再正式规划。

# 2026-10-02 决策记录：先双目，后专用前处理与 NPU

以下是用户本轮确认的方向，前处理暂只保留方案，不在双目实施时顺手加入算法或模型。
工程统一采用物理一基编号 CAM1/CAM2；上文 Camera0/Camera1 是历史示意编号。

## 已有实板基线

- CAM1 配置为640×480 RGB565，`0x4740=0x20`；完整帧为480行、307200像素、614400字节。
- 用户实板日志已显示多帧成功，DDR回读sum16与DMA累计值MATCH=YES，两个缓冲交替并成功释放。
- 当前重度CPU校验/阻塞UART导致消费慢，DMA_CODE=9为无空闲槽主动丢新帧，不是DDR容量不足。
- Camera/DVP/FIFO/DMA状态经一致性MMIO快照供CPU读取，UART不参与图像搬运。

## 后续专用前处理方案（暂不实施）

```text
DDR完整原图
    ↓
硬件颜色候选筛选：黄、红、蓝、黑
    ↓
去噪、区域合并与候选框生成
    ↓
面积/长宽比/颜色占比等粗筛
    ↓
同一帧ROI裁剪、缩放、像素格式整理、INT8量化
    ↓
独立模型输入缓冲 → NPU分类 → 类别、置信度、位置、颜色信息
```

- 路标位置不能预先确定，不把固定ROI当作最终方案；颜色只产生候选，不能独自认定路标。
- 黑色还可能来自阴影/暗背景，优先作为候选内部文字/图案的辅助特征；具体规则用实际图像验证。
- 颜色阈值和筛选参数可配置，不凭空锁定数值；须覆盖光照、曝光、白平衡变化和无目标场景。
- 专用前处理硬件可归入NPU子系统统一调度；CPU只负责参数、任务与缓冲管理，不默认逐帧全图扫描。
- 原图在裁剪结果另存后即可释放，不必等整个推理结束；模型输入在最后一次NPU读取后才能释放。
- 原图、裁剪输入、权重、输出与中间特征图必须分区，不能因为都在NPU Input区就允许地址重叠。
- AI第一版目标1～5 FPS，是每秒选取/处理画面的速率，不等于一次批量提交1～5帧。
- 96×96及灰度/RGB通道数仍是候选规格，须与模型、颜色需求和算子支持一起冻结；权重离线训练，板上执行推理。
- 待确认：是否多目标、是否识别全部目标、候选框数量上限、背景类、类别表、准确率/延迟指标。

## 本阶段优先任务：双目独立并发采集

- 不复用旧100H demo位流；复用自研且已验证的DVP/FIFO/DMA/快照模块，各路独立SCCB/RESET/PCLK。
- 两路都为640×480 RGB565，独立采集到DDR，不拼接图像，不声称已实现曝光同步、双目匹配或深度计算。
- 保留CAM1 MMIO `0x40000300` 与两槽 `0xB8000000/0xB8100000`。
- CAM2使用MMIO `0x40000400` 与独立两槽 `0xB8200000/0xB8300000`，每槽1MiB；共占输入区4MiB，剩余12MiB待后续规划。
- 两路在DDR域先仲裁，再与CPU共享DDR；必须锁定完整AW/W/B事务并将响应送回正确通道。
- 完成槽必须显式释放；无空闲槽仍丢弃新帧并计数，不添加自动最旧覆盖或15/30帧深队列。
- 双目测试消费者快速检查描述符/少量样本并归还槽；UART低频且非阻塞，不能用逐帧全图校验制造消费瓶颈。
- 每路独立报告成功/DVP/丢帧计数、尺寸、FIFO水位峰值、错误、完成地址和sum16；未完整重算DDR时不能打印MATCH=YES。
- CAM2球位严格沿用本地核对表；FPIOA18/28/29与CAM2数据共用球位时，必须硬件禁止输出驱动并记录接口占用。
- 先离线验证两路异步时钟、并发DDR访问、不同图案、不串图、释放隔离和停一路另一继续；最终PDS生成与上板由用户review执行。
- 新双目固件独立保存，不覆盖已验证单目/GPIO镜像。双目RTL/端口和loader变化必须明确通知需新位流及匹配软件镜像。

双目RTL/独立固件及离线专项回归已完成，前处理/NPU仍未实施；引脚变化、镜像长度、
SHA-256、测试证据和实板Review步骤统一见 `双目Camera_实施与实板Review.md`。
尚待用户生成新位流并进行实板验收，不把离线通过记为双目实板通过。
