# 整体目标

最终你希望得到的是：

```
                    你的 small-eyes SoC
┌──────────────────────────────────────────────┐
│                                              │
│   RISC-V CPU                                 │
│      │                                       │
│      ├── UART → MobaXterm                    │
│      │                                       │
│      ├── Camera MMIO                         │
│      │       │                               │
│      │       ├── 摄像头状态                  │
│      │       ├── 帧计数                      │
│      │       ├── 像素计数                    │
│      │       └── 错误状态                    │
│      │                                       │
│      └── SCCB/I²C配置 OV5640                 │
│                                              │
│ Camera0 ─DVP→ DVP RX0 ─┐                     │
│                         ├→ FIFO/DMA → DDR    │
│ Camera1 ─DVP→ DVP RX1 ─┘                     │
│                                      │       │
│                                      ↓       │
│                                     NPU      │
└──────────────────────────────────────────────┘
```

这里其实有两层“摄像头驱动”：

```
软件驱动
CPU C代码
负责：
OV5640配置
读取状态
UART打印
控制采集

+

硬件驱动
FPGA Verilog
负责：
DVP接收
像素拼接
FIFO
帧统计
DDR/DMA
```

这两部分合起来，才是你这个 SoC 里的完整 Camera Driver。

------

# 第一阶段：把 UART 变成正式调试接口

这个你已经验证 UART 可以正常输出，所以不是重新写 UART，而是把它做成一个小型的软件调试库。

建议增加类似：

```
bsp/
└── camera_app/
    ├── uart.c
    ├── uart.h
    └── main.c
```

至少做：

```
uart_putc();
uart_puts();
uart_puthex();
uart_putdec();
```

以后不要靠：

```
LED亮没亮
HDMI黑没黑
```

猜系统状态。

而是直接看：

```
=== Small Eyes Camera Bring-up ===

DDR INIT     : OK
CAM0 SCCB    : OK
CAM0 CHIP ID : 0x5640
CAM0 PCLK    : 24.0 MHz
CAM0 VSYNC   : 30 frames
CAM0 PIXELS  : 307200

CAM1 SCCB    : OK
CAM1 CHIP ID : 0x5640
...
```

### 第一阶段验收

MobaXterm：

```
UART TEST OK
DDR INIT OK
SYSTEM READY
```

这一步你基本已经有基础了。

# 第二阶段：先做“摄像头探活”，不要马上采图

这是你下一步最值得做的。

先只接：

```
FPGA/CPU
   │
   ├── XCLK
   ├── RESET
   ├── PWDN
   ├── SCL
   └── SDA
        │
        ↓
      OV5640
```

先不管：

```
PCLK
VSYNC
HREF
DATA[7:0]
```

目标只有一个：

> **证明 CPU 确实可以控制并识别 OV5640。**

------

## 这里要实现 SCCB

我建议第一版直接：

```
CPU
 ↓
FPIOA/GPIO
 ↓
软件模拟 SCCB
 ↓
OV5640
```

也就是 C 里面实现：

```
sccb_start();
sccb_stop();

sccb_write_byte();
sccb_read_byte();

ov5640_write_reg();
ov5640_read_reg();
```

例如：

```
uint8_t ov5640_read_reg(uint16_t reg);
```

------

## 然后读取 OV5640 ID

OV5640 通常可以通过：

```
0x300A
0x300B
```

读取芯片 ID。

预期得到：

```
0x56
0x40
```

于是 MobaXterm：

```
CAM0 probe...

SCCB ACK OK
PIDH = 0x56
PIDL = 0x40

OV5640 detected.
```

如果这一步成功，你就已经证明：

```
供电        基本正常
XCLK        基本正常
RESET/PWDN  基本正常
SCCB        正常
摄像头      活着
```

这个意义非常大。

# 第四阶段：写真正的 DVP Receiver

这一部分就是 FPGA RTL。

新增：

```
soc/camera/
├── camera_dvp_rx.v
├── camera_pixel_pack.v
├── camera_status.v
└── camera_regs.v
```

输入：

```
cam_pclk
cam_vsync
cam_href
cam_data[7:0]
```

输出：

```
pixel_data[15:0]
pixel_valid
frame_start
frame_end
line_valid
```

如果 OV5640 输出 RGB565：

```
PCLK #1
8 bit
    \
     → 16-bit RGB565 pixel
    /
PCLK #2
8 bit
```

# 第五阶段：专门做 Camera Debug Registers

这是我特别建议你加的。

不要让 CPU直接去“猜”DVP有没有工作。

给摄像头做 MMIO，比如：

```
0x40000300 CAMERA0_CTRL
0x40000304 CAMERA0_STATUS
0x40000308 CAMERA0_FRAME_CNT
0x4000030C CAMERA0_PIXEL_CNT
0x40000310 CAMERA0_PCLK_CNT
0x40000314 CAMERA0_ERROR
```

例如：

### STATUS

```
bit 0 : camera enabled
bit 1 : PCLK detected
bit 2 : VSYNC detected
bit 3 : HREF detected
bit 4 : frame received
bit 5 : FIFO overflow
```

CPU只需要：

```
status = CAMERA0_STATUS;

uart_puts("CAM0 STATUS = ");
uart_puthex(status);
```

就能看到：

```
CAM0 STATUS = 0x0000001F
```

------

## 同时统计几个关键量

FPGA硬件自己计数：

```
PCLK数量
VSYNC数量
HREF数量
一帧pixel数量
frame数量
```

例如设置：

```
640×480
```

RGB565最终应当大致得到：

```
307200 pixel / frame
```

UART打印：

```
CAM0:
PCLK   : detected
VSYNC  : 31
FRAME  : 30
PIXELS : 307200
```

这比 HDMI 强太多。

# 第六阶段：单摄像头 → FIFO → DDR

到这里才开始碰 DDR。

结构：

```
OV5640
 ↓
DVP Receiver
 ↓
RGB565
 ↓
Async FIFO
 ↓
Camera DMA
 ↓
DDR
```

为什么需要 FIFO？

因为：

```
Camera PCLK
```

和：

```
DDR / SoC clock
```

不是同一个时钟域。

所以：

```
camera clock domain
         ↓
     Async FIFO
         ↓
system/DDR clock domain
```

------

## Camera DMA

这里建议不要直接拿你现在 NPU DMA 硬改。

可以：

```
Hcamera_dma.v
```

第一版做得很简单：

```
frame_start
 ↓
write_addr = CAMERA_FRAME_BASE

每收到一个pixel
 ↓
写DDR
 ↓
地址++
```

例如：

```
CAM0_FRAME_BASE = 0xB8000000
```

以后双目：

```
CAM0 = 0xB8000000
CAM1 = 0xB8100000
```

具体区域以后再正式规划。

------

## 第六阶段验收

不看 HDMI。

CPU直接读 DDR：

```
uint16_t *frame = (uint16_t *)CAM0_FRAME_BASE;
```

然后串口：

```
CAM0 FRAME DONE

P0  = 0x7BEF
P1  = 0x840F
P2  = 0x83EF
P3  = 0x7C0F
...
```

甚至可以计算：

```
CRC32
checksum
min
max
```

比如：

```
FRAME 15
PIXELS : 307200
CRC32  : 0x82F7A10C
```

如果拿手挡镜头以后 CRC 改变：

```
CRC32 : 0x91342BC8
```

你就已经可以非常确定：

> 摄像头图像确实已经进 DDR 了。

# 第七阶段：确认单摄像头完全工作之后，再做双目

这是非常重要的顺序。

不要一开始：

```
Camera0 + Camera1
```

同时调。

先实现：

```
Camera0 ✔
```

然后复制硬件：

```
              ┌→ DVP RX0 → FIFO0 ─┐
Camera0 ──────┘                    │
                                   ├→ DDR
Camera1 ──────┐                    │
              └→ DVP RX1 → FIFO1 ─┘
```

------

## SCCB这里还需要确认硬件连接

双 OV5640 有个很现实的问题：

> 两颗 OV5640 的 SCCB 地址通常相同。

所以要看原 Demo / 板子硬件到底怎么解决。

可能是：

```
独立SCL/SDA
```

或者：

```
共用SCCB
+
分别控制PWDN
```

例如：

```
只唤醒 Camera0
配置 Camera0

Camera0 PWDN

唤醒 Camera1
配置 Camera1
```

这个必须根据旧 Demo 和板子连接确认。

------

# 第八阶段：双目 DDR 数据布局

这时候才决定你原 Demo 那种：

> “两个摄像头采集后拼接”

到底要不要保留。

其实对于你后面的 AI，我甚至不建议一开始硬拼成：

```
| Left | Right |
```

更干净的是：

```
DDR

CAM0 frame buffer
0xB8000000
┌──────────────┐
│ Left image   │
└──────────────┘

CAM1 frame buffer
0xB8100000
┌──────────────┐
│ Right image  │
└──────────────┘
```

需要拼接的时候再处理。

这样对：

```
NPU
CPU
调试
```

都更灵活。

------

# 最后才是 HDMI

HDMI可以放到最后。

因为你的核心目标实际上是：

```
Camera
 ↓
DDR
 ↓
NPU
```

不是：

```
Camera
 ↓
电视机
```

所以 HDMI 只是辅助验证工具。

等 Camera→DDR 完全稳定以后：

```
DDR
 ↓
HDMI Reader
 ↓
HDMI OUT
```

再加回来。
