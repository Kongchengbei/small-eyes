# BRAM 配置 CPU 执行拍数优化任务

## 当前基线与范围

- 配置入口：`Kconfig` 的 `SOC_PROFILE_BRAM`。
- 当前 `soc/soc_addr_map.vh`：CPU 70 MHz，BRAM 开启，ICache、DCache、DDR、Camera 和预处理关闭。
- 用户实板结果：3000 次迭代，1206606019 ticks，174.04190 CoreMark，2.48631 CoreMark/MHz。
- 2026-10-11 18:18:16 映射报告：整个 SoC 为 4342 LUT；按上述分数计算约为 0.04008335 CoreMark/LUT。此数字不是 CPU 层级资源统计。
- 2026-10-11 18:20:14 时序报告：70 MHz，CPU setup WNS +1.235 ns，估计频率 76.6246 MHz。

本轮目标是在相同频率、固件、内存配置和迭代次数下减少执行拍数。优化针对通用指令行为，不根据 CoreMark 地址、常量、输入或特定指令片段设置专用通路。

现有连续 BRAM 取指已经支持每拍交付一条指令。现有 MEM 前递也已经在响应有效的当前拍使用 load 返回值，因此不能把这两项当作尚未实现的收益。

用户已审核并授权实施。下列三项已由 Luna high 实现并经主代理复核，修改位于 `cpu/Hidu.v`、`cpu/Hexu.v`、`cpu/Hifu.v` 和 `cpu/Htop.v`。普通 ALU 前递仅在 BRAM 模式启用，生产配置、时钟、固件和厂商 RAM IP 未修改。

## 任务 1：普通整数运算的 MEM→EX 前递

位置：`cpu/Hidu.v`、`cpu/Hexu.v`、`cpu/Htop.v`；复用 `cpu/Hmemu.v` 的格式化 load 返回值与有效信号。

### 当前开销

`Hidu.v` 的 `ex_load_stall` 检测 EX load 的目的寄存器是否等于 ID 的源寄存器。命中时，无论使用者是否必须在 ID 读取结果，都暂停 ID。

例如：

```asm
lw  a0, 0(a1)
add a2, a0, a3
```

| 周期 | 当前实现 | 修改目标 |
| --- | --- | --- |
| N | load 在 EX；add 在 ID 停住 | load 在 EX；add 获准进入 EX |
| N+1 | load 在 MEM 返回；add 在 ID 获取返回值 | load 在 MEM 返回；add 在 EX 使用返回值计算 |
| N+2 | add 在 EX 计算 | add 已进入 MEM |

在 BRAM 响应及时且没有其他背压时，每个符合条件的相邻依赖争取消除一拍。

### 修改任务

1. 第一阶段仅放行在 EX 使用寄存器操作数的普通整数 ALU 指令；分支、JALR、CSR、乘除法和访存指令保留原停顿规则。
2. ID 发给 EX 的信息增加每个源操作数的待前递标记和对应寄存器标识。只有确实依赖尚未完成的较新生产者时才置位，不能让无关的 MEM 写寄存器覆盖已有操作数。
3. 在 `Htop.v` 接入 MEM 前递的有效信号、目的寄存器和格式化结果到 EX。
4. EX 在标记命中、目的寄存器匹配且结果有效时，用 MEM 返回值替换相应寄存器操作数；PC、立即数和零操作数的选择保持其原有语义。
5. 数据尚未有效时保持 EX，不发布有效前递结果，也不让该指令进入 MEM。
6. 如果返回值已经有效但 EX 因其他原因不能离开，锁存返回值并清除对应待前递标记。之后即使 MEM 换成另一条指令，EX 仍使用已经取得的正确值。
7. 保留 x0、较新写者优先、flush 清除和 MMIO 响应等待规则。

### 代价与边界

增加操作数选择、依赖信息寄存器和等待控制。新路径可能经过 BRAM 返回、load 格式化、EX ALU，因此必须重新检查 70 MHz 时序，尤其是已有 EX 长路径。

`load → branch/JALR` 仍需在 ID 获得结果，不属于本任务可消除的气泡。不得仅删除 `ex_load_stall`。

## 任务 2：除法完成当拍放行 EX

位置：`cpu/Hexu.v`；第一阶段不改 `cpu/div.v` 的迭代算法。

### 当前开销

代码已有 `div_done_fire = ex_m_is_div && ex_div_started && div_done`，但 `ex_ready_go` 和 EX 前递只使用寄存器 `ex_div_done`。

因此除法器 `done` 和结果已经有效时，还要经过一个时钟沿将完成状态锁存到 EX，下一周期才能放行。乘法已经使用 `ex_mul_done || mul_done_fire`，不存在同一种完成握手等待。

### 修改任务

1. 增加 `ex_div_ready = ex_div_done || div_done_fire`。
2. EX 放行条件和除法结果前递有效条件统一使用 `ex_div_ready`。
3. MEM 有背压时继续锁存完成状态；结果尚未有效时不放行。
4. 保持除零、有符号溢出、商与余数选择、flush 和启动握手行为。

无其他背压时，每条 DIV、DIVU、REM、REMU 可减少一拍 EX 占用。正常除法仍需要原有 32 轮运算，不能将这项收益描述成单拍除法。

此项改动较小，适合在任务 1 之前先实施和单独记录收益；整段程序收益仍取决于实际除法执行次数。

## 任务 3：BRAM 重定向当拍提交目标取指

位置：`cpu/Hifu.v`；限定同步、固定响应延迟的连续 BRAM 取指模式。

### 当前开销

`imem_addr` 在 flush 时已经选择 `redirect_pc`，但 `imem_req_valid` 同时被 `!flush` 清零。于是 flush 当拍没有目标请求，下一拍才发起 BRAM 读取。

### 修改任务

1. BRAM 模式下，flush 当拍允许提交目标取指请求；目标请求优先于原队列容量限制，因为原队列会被丢弃。
2. flush 分支清除旧 IF/skid 数据与旧响应关联信息，同时记录新请求的目标 PC 和 pending 状态。
3. 若目标请求被接受，不在下一拍重复使用 `force_fetch` 请求相同目标；未接受时保持重试机制。
4. 下一拍处理的是正确目标的 BRAM 响应，原路径响应不得混入；预测信息必须与目标指令的 PC 对齐。
5. 保持 EX 异常重定向高于 ID 分支重定向的优先级。
6. DDR/Cache 模式保留原请求取消和等待机制。

无额外阻塞时，每次重定向争取减少一拍恢复等待；不改变预测准确率。

主要代价是 flush 到 BRAM 取指地址/请求的时序要求更直接，需要重新布局布线确认。

## 后续候选：根据执行停顿分布排序

下面几项暂不加入第一轮实现，避免在没有执行占比证据时扩大资源和控制逻辑：

- 乘法提前启动或与后续流水级重叠：现有乘法为两级计算，但 EX 原地等待。需要重新安排结果携带与冒险控制，不能直接允许未完成乘法离开 EX。
- BTB 扩容、索引调整和返回地址栈：现有 16 项直接映射预测器可能存在冲突；是否划算需统计预测错误的类型和频度。
- 除法提前结束或多位迭代：先看通用 DIV/REM 等待占比，再权衡组合路径、LUT 与拍数。
- load 后 store 数据前递及其他 EX 消费者：普通 ALU 前递稳定后再扩展，访存副作用必须严格受有效操作数和握手控制。

代码审查能确认每次事件中的额外拍数，不能确认 CoreMark 动态执行时的收益排序。应区分 load-use、乘除法等待、MEM 等待、取指空拍和重定向开销；同一拍有多个阻塞原因时不能简单相加。

## 实施与验收

建议实施顺序：任务 2 → 任务 1 → 任务 3。先处理小范围、确定的一拍开销，再增加前递和取指控制。

按用户要求，不新增中间 testbench；实施结束后统一使用现有指令测试入口验证。验证配置必须明确为 BRAM，并覆盖前递优先级、load-use、字节/半字扩展、乘除法、分支/JALR、背压、MMIO 和错误路径无副作用。供应商 RAM 端口时序仍使用现有相关验证入口核对。

性能与资源验收使用同一份生产固件及同样的 3000 次迭代：

1. 总 ticks 低于 1206606019，CoreMark CRC 正确。
2. 固定 70 MHz，CoreMark/MHz 高于 2.48631。
3. 新分数除以同口径的新 LUT 数，高于对应 BRAM 基线；如果赛事要求 CPU 层级 LUT，则前后均重新统计 CPU 层级。
4. 70 MHz setup、hold 等时序检查通过。

若以整个 SoC 的 4342 LUT 为基线，资源效率提升要求：

```text
新 CoreMark / 174.04190 > 新 LUT / 4342
```

例如 LUT 增加 5%，则 CoreMark 必须提升超过 5%，才能改善 CoreMark/LUT。关闭 DDR 等外设产生的资源变化应另行记录，不能混入同配置的 CPU 修改收益。

短迭代仿真可以检查功能和周期趋势，不能替代生产固件的正式跑分。

## 本次实施结果

- 除法完成状态直接参与 EX 放行和前递；原有背压下的完成状态保存保留。
- ID 对普通 ALU 发出逐源待前递标记。两个操作数共用一个生产者寄存器标识，EX 精确匹配有效 MEM 结果，必要时保存到原操作数寄存器。
- EX 操作数未就绪时禁止放行和结果前递；原 `ex_allowin` 已阻止年轻指令进入 EX 或在 ID 发布重定向，因此没有另加容易使非写寄存器指令误停顿的通用 rd 停顿判断。
- 连续 BRAM 取指在 flush 当拍接受目标请求，记录正确目标的响应关联并丢弃旧 IF/skid 工作；DDR 取指方式保留。
- 新增 `sim/cpu_bram_forward.S` 为综合指令程序，复用现有 `tb_Htop`，未新增 testbench。
